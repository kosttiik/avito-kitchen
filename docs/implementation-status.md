## Известные ограничения

- Идентификатор пользователя нельзя считать доверенным, пока его не подставляет шлюз основной платформы.
- Доступность логическая и не резервирует количественные остатки.
- Опрос добавляет ограниченную задержку; повторное наблюдение заказа возможно.
- Состояние примера заведения намеренно хранится в памяти; PostgreSQL основного сервиса остаётся долговременным источником истины.
- Демонстрационный ключ и операторский API предназначены только для локальной разработки.
- Оплата, курьеры, геопоиск и уведомления находятся вне согласованного MVP.

## Примечания к реализации

- Диаграмма C4 уровня 2 — самостоятельный исходник PlantUML без скопированной библиотеки C4-PlantUML. Это сохраняет воспроизводимость и семантику контейнерной диаграммы.
- Небольшой сервис примера заведения оставлен единым связным пакетом с отдельными файлами сервиса и HTTP, а не разбит на три пакета с одним типом. Его процесс и интеграционная граница остаются независимыми от основного API.

## Следующее однозначное действие

Незавершённых пунктов реализации нет. Новый агент или ревьюер сначала выполняет требования `AGENTS.md`, проверяет `git status` и запускает `make verify`. Любое изменение поведения должно сначала обновить требование, критерий приёмки и этот журнал. Отправка в удалённые репозитории не выполнялась. После явного согласия пользователя нужно создать проверенный коммит в `main`, отправить его в `origin` и только после успеха отправить тот же коммит в `personal`.
