# Инструкция для AI-агента

Перед изменением репозитория:

1. Выполнить `git status --short --branch` и сохранить несвязанные изменения пользователя.
2. Полностью прочитать `backend-trainee-assignment-autumn-2026.md`.
3. Полностью прочитать `docs/spec.md`.
4. Полностью прочитать `docs/implementation-status.md`.
5. Сверить файл состояния с репозиторием и фактическим выводом команд.

Порядок источников истины:

```text
Исходное задание
    → спецификация и критерии приёмки
    → пути пользователя и заведения
    → архитектура, API и схема базы данных
    → тесты
    → реализация
```

Нельзя менять вышестоящий артефакт только ради соответствия существующему коду. При обнаружении фундаментальной ошибки сначала обновляются решение и связь требований с проверками, затем тесты и только после этого реализация.

Бизнес-поведение реализуется вертикальными срезами. Для каждого среза нужно начать с требования и критерия приёмки, написать тест, подтвердить его ожидаемое падение, реализовать минимальное поведение, выполнить соответствующие проверки качества и обновить `docs/implementation-status.md`: указать подтверждённые результаты и следующее однозначное действие.

Нельзя хранить секреты в документации. Нельзя утверждать, что команда или сценарий прошли, если они фактически не запускались.
